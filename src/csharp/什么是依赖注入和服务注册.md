## 什么是依赖注入和服务注册？

> 依赖注入就是组件不自己 `new` 依赖，而是通过框架把依赖传进来。服务注册就是告诉框架：这个依赖用哪个实现的，活多久，谁可以拿到它。



前端里类似`Vue`的`Provide`和`inject`



自己创建：

```
function ProductPage() {
  const api = new ApiClient() // 页面自己造依赖
  api.get('/products')
}
```

从外面注入：

```
function ProductPage() {
  const api = useApi() // 框架/上层已经准备好了，这里只拿来用
  api.get('/products')
}
```

第二种就是依赖注入。页面只声明「我需要一个 API 客户端」，不关心它是怎么连上后端、token 放哪、超时多久。这些在应用启动时配一次。



.net里面对应的构造函数注入：



```csharp
public class ProductService(RedisClient redis)
{
    public Task<string?> GetNameAsync(int id)
        => redis.GetAsync($"product:{id}");
}
```

`ProductService` 没有 `new RedisClient()`。它只说：我需要一个 `RedisClient`。框架创建 `ProductService` 时，自动把已经注册好的那个 Redis 客户端传进来。

## 服务注册是什么

前端里，你得先在根组件把东西放进去，子组件才能 `useContext`：



```
function App() {
  const api = useMemo(() => new ApiClient(config), [])
  return (
    <ApiContext.Provider value={api}>
      <ProductPage />
    </ApiContext.Provider>
  )
}
```

.NET 的「根组件」是 `Program.cs`。启动时往容器里登记：



```
builder.Services.AddSingleton(sp =>
{
    return new RedisClient(builder.Configuration.GetConnectionString("Redis"));
});
```

这句话的意思是：

- 有人要 `RedisClient` 时，用这个工厂方法创建。
- `AddSingleton` 表示整个进程只创建一次，之后谁要都拿同一个。

之后控制器、服务只要在构造函数里写上 `RedisClient redis`，框架就会从容器里取出来传进去。你不用在每个接口里写连接串。

## 三种生命周期，用前端状态来理解

| .NET           | 活多久                   | 前端类比                                       |
| -------------- | ------------------------ | ---------------------------------------------- |
| `AddSingleton` | 进程启动到关闭，全局一份 | 模块外的单例、`Pinia` 根 store、应用级 Context |
| `AddScoped`    | 一次 HTTP 请求一份       | 一次路由导航、一次请求里的临时状态             |
| `AddTransient` | 每次要的时候都新建       | 每次调用 `createClient()` 都得到新对象         |

## 系统自带的服务注册

| 方法                                          | 干什么                                                  |
| --------------------------------------------- | ------------------------------------------------------- |
| `AddSingleton` / `AddScoped` / `AddTransient` | 三个生命周期的基础注册                                  |
| `AddControllers`                              | Web API 控制器、路由、JSON                              |
| `AddAuthorization`                            | 授权策略                                                |
| `AddAuthentication`                           | 认证，后面再接 `.AddJwtBearer()`                        |
| `AddCors`                                     | 跨域，前端联调几乎必用                                  |
| `AddHttpClient`                               | 登记一个可注入的 `HttpClient`，相当于封装好的请求客户端 |
| `AddOptions` / `Configure<T>`                 | 把 `appsettings.json` 绑到一个配置类                    |
| `AddMemoryCache`                              | 进程内缓存                                              |
| `AddHealthChecks`                             | 健康检查接口                                            |
| `AddEndpointsApiExplorer`                     | 给 Swagger 提供最小 API 的元数据                        |

`AddControllers()` 一次会登记很多服务。你不用自己把 JSON、模型绑定、过滤器一个个 `AddSingleton`。这和 `app.use(router)` 一次装好路由、历史记录、导航守卫是同一类设计。

## 装了包才出现的

包没装时，这些方法在编译期就不存在，和没装 `vue-router` 就没有 `createRouter` 一样。

| 方法                            | 来自哪个包                                        | 干什么                                     |
| ------------------------------- | ------------------------------------------------- | ------------------------------------------ |
| `AddDbContext<T>`               | `Microsoft.EntityFrameworkCore`                   | 登记数据库上下文，默认一次请求一个         |
| `AddSqlServer` / `UseNpgsql` 等 | 对应数据库提供程序                                | 接在 `AddDbContext` 后面，指定用哪种数据库 |
| `AddStackExchangeRedisCache`    | `Microsoft.Extensions.Caching.StackExchangeRedis` | 分布式缓存，底层是 StackExchange.Redis     |
| `AddSwaggerGen`                 | `Swashbuckle.AspNetCore`                          | Swagger 文档                               |
| `AddJwtBearer`                  | `Microsoft.AspNetCore.Authentication.JwtBearer`   | JWT 校验                                   |

## 怎么判断该用哪个

看你要注入的类型，反查谁负责登记它。

- 要注入 `RedisClient`：没有现成的 `AddXxx`，用 `AddSingleton` 自己登记。
- 要注入 `IDistributedCache`：用 `AddStackExchangeRedisCache` 或 `AddDistributedMemoryCache`。
- 要注入 `AppDbContext`：用 `AddDbContext<AppDbContext>`。
- 要注入 `HttpClient`：用 `AddHttpClient`。
- 要注入自己的 `ProductService`：框架不会替你发明方法，写 `AddScoped<ProductService>()`。

## 对照三个生命周期

| 方法           | 活多久                   | 前端类比                                     |
| -------------- | ------------------------ | -------------------------------------------- |
| `AddSingleton` | 进程启动到关闭，全局一份 | 应用级 Context、根 store。整个网站共用同一个 |
| `AddScoped`    | 一次 HTTP 请求一份       | 这一次页面请求里的临时状态。请求结束就丢掉   |
| `AddTransient` | 每次注入都新建           | 每次调用工厂函数都 `new` 一个新对象          |

## 怎么选

- 连接、客户端、配置：`AddSingleton`
- 业务服务、数据库上下文：`AddScoped`
- 无状态小工具：`AddTransient`

拿不准时，业务服务用 `AddScoped`。它和「一次接口调用」对齐，也避免把请求里的数据误存进全局单例。
